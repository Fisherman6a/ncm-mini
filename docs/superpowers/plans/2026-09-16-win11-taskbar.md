# Windows 11 Taskbar Implementation Plan

> **For agentic workers:** Use `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox syntax for tracking. This is the original staged plan, not a claim that every planned feature is complete. See `docs/win11-player-integration.md` for the current implementation and verification scope.

> 2026-09-16 更新：用户已授权并推进正式歌曲数据/控制接入，见 `docs/win11-player-integration.md`。当前实现了独立 Win11 绘制复用现有后台，并未把旧 DeskBand 绘制重构为共用 PlayerView；安装、完整布局恢复和所有系统组合验收仍未完成。

**Goal:** 保留现有 DeskBand，新增 Win11 原生任务栏窗口，共用歌曲信息、播放控制、设置和界面绘制。

**Architecture:** 在现有 `NCMMini.exe` 内增加 Win32 窗口，通过 `SetParent` 嵌入 `Shell_TrayWnd`。使用 UI Automation（Windows 提供的界面元素查询接口）读取任务栏占用区域，计算空位；旧 DeskBand 继续通过现有命名管道通信，新窗口在进程内接收状态和提交命令。

**Tech Stack:** C++17、Win32、GDI、Windows UI Automation、现有 MinGW 构建脚本、PowerShell 7。

**Spec:** 本文“范围与行为约定”，依据本任务用户已提出的“保留现有作为兼容，增加 Win11 逻辑”和“参考 SPlayer 源码”。用户已安装工具链，并授权开始最小链路开发。

## Global Constraints

- 不安装工具、编译器或依赖；需要工具链时先查找现有路径，确实缺失再请求用户授权。
- 不引入 Rust、Electron、WPF 或 WinUI；复用当前 C++ 工程。
- 旧 DeskBand 的 COM 类标识、管道名称、协议版本和命令编号不变。
- 不修改网易云音乐状态识别、歌词计时和播放控制机制。
- 不自动重启 Explorer 来修复新模式，不修改用户任务栏布局设置。
- 构建、运行、安装和重启 Explorer 测试分开；构建本身不得停止用户程序或改动已安装版本。
- 使用 `pwsh -NoProfile`，外部命令失败时检查 `$LASTEXITCODE`。
- 只有实际运行过的构建和测试才标记通过，静态检查单独记录。

## 范围与行为约定

1. 首版显示在主显示器任务栏，支持居中和左对齐、浅色和深色、自动隐藏、显示器缩放变化。主显示器切换后重新定位；每个副屏同时显示独立控件留作后续扩展。
2. 新增 `--taskbar auto|win11|deskband`，默认 `auto`，保留 `--no-show-band` 语义。显式选择某模式时不静默切到另一种模式。
3. `auto` 结合系统 build 和任务栏实际能力选择。Win11 优先尝试新窗口；确定不支持时仅在旧宿主可用的情况下回退 DeskBand。Explorer 启动中、UIA 暂时无结果或空间不足属于等待状态，不反复切换模式。
4. 优先选择应用图标左侧的可用空位，放不下时尝试右侧；没有足够宽度时逐步隐藏封面和文字，保留三个播放按钮。三个按钮也放不下就隐藏控件，空位恢复后重新显示。
5. 占用区域包括开始、搜索、任务视图、应用按钮、Widgets 和系统托盘等可见内容；不能只依靠几个固定元素名假定其他区域全是空白。无法可靠确认边界时隐藏并重试。
6. 使用窗口嵌入后，Windows 不会自动为控件预留空间。布局扫描和后续重排必须避免覆盖现有按钮；不向系统按钮集合插入元素。
7. UIA 调用在独立工作线程执行，结果带任务栏代次号，旧任务栏的扫描结果不得应用到新窗口。播放状态采用有锁的最新快照和消息通知，避免跨线程直接绘制以及销毁后悬空指针。
8. 新窗口自己的 UI 线程处理窗口消息；窗口点击将命令排队，由主程序执行，避免 `PlayerController::Send` 的超时等待阻塞界面。设置修改也发布到该线程。

## 当前核查结果

- `src/NCMMini.HostCpp/main.cpp` 的 `Application::Run` 负责启动管道、显示 DeskBand 和发布 `BandState`；重复启动分支也直接调用旧控制器。
- `src/NCMMini.Band/NCMMiniBand.cpp` 将 COM、窗口、绘制、点击和管道处理写在一起；绘制与命令命中部分可小范围提取。
- `src/Common/Settings.h` 已有共用设置；新模式通过主程序的设置回调更新，不依赖只查找旧窗口类名的通知。
- `scripts/install.ps1` 强制注册 DLL、调用旧控制器，并在失败时重启 Explorer；`run-dev.ps1` 也强制注册 DLL，必须增加模式分支。
- `scripts/build.ps1` 在编译前停止程序，在替换失败时重启 Explorer，需将编译输出与安装更新分离。
- 用户现已安装 WinLibs GCC 16.1.0，原有三个产物及独立验证程序均已实际编译；未运行安装脚本。

## Task 1: 最小嵌入验证

**Files:** `Win11TaskbarWindow.h/.cpp`、`TaskbarLayout.h/.cpp`、`TaskbarScanner.h/.cpp`、`tools/TaskbarProbe.cpp`、`tests/taskbar_layout_tests.cpp`、`scripts/build.ps1`、`scripts/build-taskbar-probe.ps1`、`scripts/toolchain.ps1`。

**接口约定:** `Win11TaskbarWindow::Start()` 返回初始化结果；`Stop()` 幂等释放线程和窗口。诊断程序单独编译，不接管现有播放器生命周期。

- [x] 检查现有编译器路径、Windows UI Automation 头文件和链接能力；用户自行安装的工具链已通过编译验证。
- [x] 分离构建副作用，独立验证程序输出到 `artifacts/taskbar-probe`；原有产物验证输出到 `artifacts/toolchain-check`。
- [x] 创建隐藏原生窗口，设置 `WS_CHILD`、清除 `WS_POPUP`，调用 `SetParent` 并校验实际父窗口和位置。
- [x] 在创建 HWND 前匹配任务栏 DPI 上下文，本机 200% 缩放实测通过。验证程序仅面向 Win11，旧模式的动态 API 回退留到主程序接入。
- [x] UIA 确认空位后显示测试按钮；实际像素、中间及两端命中、真实点击、不抢焦点和退出清理自检通过。
- [x] 使用 GDI+ 绘制预乘 Alpha 内容，通过 `UpdateLayeredWindow` 合成；默认封面、文件封面、三个按钮、圆角悬停、按下反馈和真实鼠标移出已验证。空白处保留 1/255 Alpha 接收鼠标，圆角外完全透明。

**本阶段 UI 补充:** `TaskbarView.h/.cpp` 是独立验证程序的绘制实现，尚未提取成新旧模式共用的 `PlayerView`。新增 `tests/taskbar_view_tests.cpp` 和 `tools/TaskbarMouseTest.cpp`；完整验证范围见 `docs/win11-taskbar-validation.md`，不将演示按钮状态当作真实播放状态。

**验收:** 主任务栏内可见且可点击，任务栏原按钮仍可用，无额外任务栏图标，退出后无残留。此阶段未通过，不扩大修改旧 UI。

- [ ] 添加测试：常规宽度三个按钮各自命中；紧凑模式无负尺寸；文字和封面不覆盖按钮；100%、150%、200% 缩放后边界一致；控件边界外无命中。

- [ ] 旧模式维持现有尺寸和外观；新模式使用可收缩布局。封面仍接收当前 40x40 像素数据，只缩放显示，不修改传输格式。
- [ ] 保留现有上一首、播放/暂停、下一首和右键选项/退出行为；不新增当前数据无法判断的播放状态。
- [ ] 编译 DLL 和主程序，运行布局命中测试；在有 DeskBand 宿主的 Win10 环境比对外观和命令行为。

**验收:** 同一份内容绘制能用于两种宿主，旧协议和行为保持兼容；没有 Win10 测试环境时明确标记旧路径实测待完成。

- [ ] 将 `Application::Run` 两处 `pipe.Publish` 接到统一发布入口。旧模式保留管道；新模式发布进程内快照，不增加第二个管道客户端。
- [ ] 新窗口点击先进入命令队列，主程序取出后调用现有 `HandleCommand`；退出时停止接收命令，再关闭窗口和工作线程。
- [ ] 在 `UpdateSettings` 路径通知新窗口，更新字体、颜色和歌词显示；旧设置通知保持可用。
- [ ] 新增隐藏顶层控制窗口，处理重复启动的显示请求和状态查询。新增 `--taskbar-status`，只查询正在运行的实例，不启动或关闭网易云音乐；状态区分可见、等待布局、等待任务栏和失败。
- [ ] 修改重复启动分支，通知已有实例，避免 Win11 模式再调用 `NCMMiniBandCtl.exe show`。

**验收:** 新模式显示真实歌曲/封面/歌词，三个播放命令和右键菜单可用；设置即时生效，重复启动不创建第二个控件，退出不留工作线程。

## Task 4: 完整空位计算

**Files:** `TaskbarLayout.h/.cpp`、`PlayerView.h/.cpp`、`taskbar_layout_tests.cpp`。

**接口约定:** `TaskbarSnapshot` 包含任务栏屏幕矩形、DPI、可见占用矩形及有效性；纯布局函数 `ChoosePlacement` 接收快照和内容尺寸，返回相对父窗口的矩形、完整/紧凑/隐藏模式。

- [ ] 构造测试：任务栏范围 `[0,1000]`、左组件 `[0,120]`、应用 `[400,600]`、托盘 `[850,1000]` 时，安全空位为 `[120,400]` 与 `[600,850]`；选中矩形必须落在空位内。
- [ ] 扩展测试：左对齐、Widgets 在右侧、任务视图、无空位、元素重叠、无效 UIA 矩形、负屏幕坐标和混合 DPI；对每个结果断言不与已知占用矩形相交。
- [ ] UIA 扫描以任务栏为根，读取可见元素边界，结合 `TrayNotifyWnd` 排除托盘。排除自身窗口和整条任务栏容器，避免把父容器当作占用或把未知内容当作空白。
- [ ] 在物理屏幕坐标下归一化和裁剪矩形，合并占用区间再求剩余区间；按 DPI 缩放留白，最后转为父窗口客户区坐标。
- [ ] 实现“完整内容 -> 减少文字/隐藏封面 -> 仅按钮 -> 隐藏”的顺序，布局保持在确认可用的范围内。
- [ ] 对同一区域的连续更新复用位置，只有空间条件变化时调整，避免每次歌词更新导致窗口移动。

**验收:** 左对齐/居中和不同应用数量下控件不遮挡系统按钮；任务栏满时隐藏，重新有空间时恢复。

## Task 5: 任务栏变化与恢复

**Files:** `Win11TaskbarWindow.h/.cpp`、`TaskbarLayout.h/.cpp`、`TaskbarPresenter.h/.cpp`、`docs/win11-taskbar-validation.md`。

- [ ] 隐藏顶层通知窗口接收 `TaskbarCreated`、显示器和设置变化；不能只依赖嵌入的子窗口接收广播。
- [ ] 订阅 UIA 结构/边界变化、托盘位置变化和相关设置变化；将密集事件合并后重算，低频检查作为漏事件补偿，禁止每次播放轮询都完整扫描 UIA。
- [ ] 将任务栏句柄和进程身份一起校验。Explorer 重启后递增代次、清理旧订阅并重新获取 HWND；嵌入子窗口若被销毁就重建，主通知窗口继续运行。
- [ ] 对短暂 UIA 无结果安排有限的快速重试，之后低频重试；不保存失效 COM 元素、不阻塞窗口线程、不把瞬时失败当作永久不支持。
- [ ] 自动隐藏时跟随父任务栏，不显示独立置顶条；恢复、主显示器切换或 DPI 变化时重新生成字体、布局和绘制面。
- [ ] 检查退出与扫描回调并发，先停止通知来源再释放对象，保证停止流程可重复调用。日志记录状态转移，不逐帧刷屏。

**验收:** 应用图标增减、托盘变化、对齐切换、自动隐藏、缩放/主屏切换均能恢复；经用户允许的 Explorer 重启实测后，控件重新出现且按钮可用。

## 回退约定

- 通过显式 `--taskbar deskband` 验证旧路径，但仅适用于支持旧宿主的系统；原生 Win11 不承诺旧模式可用。
- 新功能失败时保留用户配置和原有构建产物，停止新窗口即可撤销窗口嵌入，不需要改动 Explorer 文件或任务栏注册表布局。
- 开发按阶段保留可审核的改动，不在未获授权时提交、发布或安装。后续用户已授权正式主程序接入及 Git 提交/push；当前验收结果见 `docs/win11-player-integration.md`，安装流程尚未适配。
